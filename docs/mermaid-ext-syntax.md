# Mermaid Ext — канонический синтаксис

Расширение добавляет 5 типов диаграмм, которых нет в upstream Mermaid.
Код изолирован в `src/services/mermaid/ext/` и попадает в прод только при
`__MERMAID_EXT__ = true`.

Документ — **единственный источник истины** по синтаксису. Фикстуры в
`sandbox/fixtures/` обязаны ему соответствовать; движки обязаны принимать
ровно то, что здесь описано, и ничего сверх.

---

## 0. Общие правила

- **Первая значимая строка** (без пустых и без `%%`-комментариев) задаёт тип.
  Разбор — `detectType()` в `registry.ts`.
- Ключевое слово типа отделяется от остального пробелом или двоеточием:
  `waterfall`, `waterfall:`, `heatmap` — всё валидно.
- **Алиасы** (регистр не важен):

  | Канон | Алиасы |
  |---|---|
  | `waterfall` | `waterfall-variance`, `waterfall-multi`, `waterfall-scenario` |
  | `bubble` | `bubblechart` |
  | `heatmap` | `heat-map` |
  | `orgchart` | `org` |
  | `ev` | `evchart` |
  | `boxplot` | `box-plot`, `box` |
  | `treemap` | `tree-map` |
  | `radar` | `radarchart`, `spider` |
  | `voronoi` | `voronoi-diagram` |
  | `series` | — |

  Алиасы — **синонимы**: `waterfall-variance` не включает отдельный режим,
  он лишь подсказывает, что данные будут с отрицательными шагами.
- Строки-комментарии начинаются с `%%` и игнорируются везде.
- Пустые строки игнорируются.
- Отступы в начале строки не значимы (обрезаются).
- **Ошибка разбора** — структура `ExtParseError { message, line (1-based), col (0-based) }`.
  Движок возвращает `{ ok: false, errors: [...] }`, а не бросает исключение.
- **Ошибка рендера** — движок бросает `Error` с префиксом `[тип]`.
- Всё, что не распознано как тип расширения, возвращает `null` — работает штатный Mermaid.

### Общие директивы

| Директива | Формат | Где применимо |
|---|---|---|
| `title` | `title <текст до конца строки>` | все 5 типов |
| `mono` | `mono` / `mono invert` / `mono off` | все типы расширения |
| `x` (ось) | `x "<подпись>" <min> --> <max>` | bubble, heatmap (без min/max) |
| `y` (ось) | `y "<подпись>" <min> --> <max>` | waterfall, bubble |
| `size` | `size "<подпись>"` | bubble |

Подпись оси в кавычках **обязательна**, если содержит пробелы или запятые.
Кавычки — только двойные `"`. Внутри кавычек поддерживается экранирование `\"`.

### Чёрно-белый режим (`mono`) — все типы

```
mono            # серые фигуры на светлом холсте
mono invert     # светлые серые фигуры на тёмном холсте
mono off        # снова цвет
```

Синонимы: `mono on`, `mono inverted`, `mono inverse`.

| | `mono` | `mono invert` |
|---|---|---|
| Фигуры | тёмные и средние серые | светлые серые |
| Холст | фон темы | тёмный, если свой `background` не задан |
| Тёмная тема редактора | шкала сама становится светлой | то же, что и `mono invert` |

Что обесцвечивается:

| Тип | Что становится серым |
|---|---|
| `waterfall` | бары. Явные `colors` и `series ... color=` по-прежнему побеждают серую шкалу |
| `bubble` | цвета групп |
| `heatmap` | полосы `scale` заменяются серым рядом той же длины |
| `orgchart` | заливка и граница блоков |
| `ev` | линии PV, EV и AC |
| `boxplot`, `treemap`, `radar`, `voronoi`, `series` | цвета серий. Явный `color=` и `colors sN=` побеждают серую шкалу |

```
bubble
mono invert
title BCG, тёмная тема
x "Доля" 0 --> 10
y "Рост" 0 --> 30
data
A : x=8, y=22, size=40, group=Software
B : x=2, y=4, size=10, group=Hardware
```

## 1. `waterfall` — водопад

Показывает, как начальное значение превращается в итоговое через шаги
`+`/`-`/`=`.

```mermaid
waterfall
title Выручка 2026
y "млн ₽" 0 --> 120
=40 : Q1
+15 : Q2
+20 : Q3
=75 : Итог
```

### Директивы

| Строка | Смысл |
|---|---|
| `title <текст>` | заголовок |
| `y "<подпись>" <min> --> <max>` | подпись оси значений и явные границы шкалы |
| `grid <шаг>` | шаг сетки по Y (любое положительное число, не обязательно «круглое»); без неё — «круглые» деления |
| `axis off` / `axis on` | скрыть/показать ось и подписи делений (по умолчанию `on`) |
| `labels above\|inside\|both\|none` | где рисовать значения: над баром (по умолчанию), внутри, и там и там, нигде |
| `connectors on\|off` | соединительные линии между барами (по умолчанию `on`) |
| `break <после> --> <до> ["подпись"]` | разрыв шкалы: участок сжат, чтобы длинные бары не съедали график |
| `fontsize <px>` | базовый размер шрифта (по умолчанию 11, допустимо 6–28) |
| `mono` / `mono invert` / `mono off` | чёрно-белый режим и его инверсия для тёмной темы (см. §0) |
| `colors total=#hex increase=#hex decrease=#hex` | свои цвета баров (ключи в любом порядке, можно частично) |
| `series <имя> [color=#hex]` | начало группы (только для мульти-режима, см. ниже) |

### Размер шрифта (`fontsize`)

```
fontsize <px>
```

Масштабирует **все** тексты диаграммы: подписи колонок, деления шкалы,
значения на барах, подпись оси, легенду серий и заголовок.

- по умолчанию **11 px**;
- допустимый диапазон — **6–28 px** (значения вне диапазона прижимаются к краю);
- вместе со шрифтом растут ширина колонок, высота графика и отступы —
  подписи не налезают друг на друга;
- при базовом значении 11 геометрия совпадает с диаграммой без директивы.

```
waterfall
fontsize 16
y "млн ₽" 0 --> 1000
=120 : Q1
+180 : Q2
= : Итого H1
```

### Строки данных

```
<знак><число> : <подпись>
```

| Знак | Смысл | Пример |
|---|---|---|
| `=` | **абсолютное** значение (стартовая/итоговая колонка) | `=40 : Q1` |
| `=` без числа | **промежуточный итог**: повторяет накопленное значение | `= : Итого H1` |
| `+` | приращение вверх | `+15 : Q2` |
| `-` | приращение вниз | `-12 : Недобор` |

- Числа: целые и дробные, разделитель — точка (`12.5`), допускается `,`
  как десятичный разделитель, если нет конфликта с разделителем `:`.
  Тысячные разделители (пробел, `_`) допускаются и удаляются: `1 200`, `1_200`.
- Отрицательное абсолютное значение: `=-10 : Итог` (знак `=` + отрицательное число).
- Подпись после `:` — до конца строки, обрезается по краям. Может быть пустой.
- Порядок строк = порядок колонок. Первая колонка **обязана** быть `=` со значением.
- `= : подпись` (без числа) — колонка-итог: значение берётся из накопленного
  результата предыдущих шагов. Удобно для промежуточных итогов и повторов.
  В каждой группе `series` считается независимо.
- Если `y ... --> ...` не задан, шкала считается автоматически по min/max
  накопленных значений, с «круглым» округлением.

### Подписи значений

По умолчанию значение пишется **над** баром. Режим задаётся директивой
`labels above|inside|both|none` и может переопределяться per-step флагами
в конце строки данных (порядок любой, регистр не важен):

| Флаг | Действие |
|---|---|
| `inside` | подпись внутри бара. Если указан только он, над баром подпись не рисуется |
| `inside="<текст>"` | то же, но свой текст внутри |
| `above` | подпись над баром. Если указан только он, внутри подписи нет |
| `above="<текст>"` | то же, но свой текст над баром |
| `no-label` | без подписи значения |
| `label=<текст>` / `label="<текст>"` | общий текст для позиции, у которой нет своего, например `label="−12 %"` |

Флаги строки задают позиции **целиком** и не дополняют общий режим:
`labels above` и строка с одним `inside` рисуют подпись только внутри.
Чтобы получить обе, нужны оба флага (или `labels both` без флагов на строке).

`inside` и `above` можно ставить одновременно, и тексты у них могут
различаться. Порядок флагов любой, регистр не важен.

```
waterfall
y "млн ₽" 0 --> 200
=90 : Q1 inside
+60 : Q2 inside="60" above="+60 млн"
-25 : Q3 above
= : Итог inside above
```

- Q1 — только внутри, над баром число не дублируется.
- Q2 — обе подписи сразу и с разным текстом: внутри `60`, над баром `+60 млн`.
- Q3 — только над баром.
- Итог — обе позиции с одним и тем же числом.

Если текст не влезает внутрь бара, он переносится над бар **одной** копией,
а не рисуется дважды. Если подпись над баром налезает на соседнюю колонку,
она автоматически поднимается выше. Глобально для всех баров — `labels both`.

Общий режим и точечные флаги на одном графике: у Q1 действует `labels inside`,
у Q2 флаг `above` заменяет его (внутри подписи нет), у Q3 подписи нет вовсе.

```
waterfall
labels inside
=40 : Q1
+15 : Q2 above label="+15 %"
-8 : Q3 no-label
```

### Разрывы шкалы (`break`)

```
break <после> --> <до> ["подпись"]
```

Участок шкалы `(после, до)` **вырезается**: значения внутри него не занимают
места на оси вообще, а на стыке видимых участков рисуются две пунктирные
линии. Нужен, когда один бар на порядок больше остальных: без разрыва мелкие
шаги превращаются в полоски.

- Пиксели на единицу считаются по **видимым** участкам (шкала минус вырезы),
  поэтому данные по обе стороны разрыва становятся крупнее, а масштаб
  одинаковый по всей высоте.
- Бар, пересекающий разрыв, **не закрашивается сквозь вырез**: он рисуется
  кусками, которые **заканчиваются ровно на линии разрыва** (бар и ось
  синхронны), а на линии добавляется «зигзаг» — общепринятый знак обрыва.
- Разрывов может быть несколько; они **не должны пересекаться**.
- Разрыв вне диапазона шкалы (`y ... --> ...`) игнорируется, а не ломает рендер.
- Деления сетки, попавшие внутрь разрыва, не рисуются; деления на границах
  разрыва (`после` и `до` лежат на одной высоте) схлопываются в одно.
- Подпись выводится справа над линией разрыва, с вырезом под текст.

```
waterfall
y "млн ₽" 0 --> 1000
break 300 --> 800 "разрыв шкалы"
=120 : Q1
+180 : Q2
+700 : Q3
```

### Примеры в редакторе

Водопад в редакторе разбит на несколько примеров — проще читать и копировать:

| Пример | Что показывает |
|---|---|
| Водопад — база | старт, рост, падение, итог (`=`, `+`, `-`) |
| Водопад — разрыв шкалы | `break` + зигзаг на баре |
| Водопад — несколько серий | `series ... color=` и оттенки роста/падения |
| Водопад — ч/б инверсия | `mono invert` для тёмной темы |
| Водопад — подписи и линии | `inside` / `above` по отдельности и вместе с разными текстами, `connectors on`, `colors` |
| Водопад — без линий | те же данные с `connectors off` — чистый вид для презентации |
| Водопад — ч/б режим | `mono` |

```
waterfall
y "млн ₽" 0 --> 1000
break 300 --> 800 "разрыв шкалы"
=120 : Q1
+180 : Q2
+700 : Q3
```

### Соединительные линии (`connectors`)

По умолчанию между барами идёт пунктирная линия — она показывает, на каком
уровне «висит» следующий шаг. `connectors off` убирает их (частый запрос для
презентаций).

**Как добавить линии:** это директива, отдельная строка, а не флаг в строке
данных. `connectors on` — включить (по умолчанию и так включено),
`connectors off` — выключить.

```
waterfall
y "млн ₽" 0 --> 200
connectors on
=90 : Q1
+60 : Q2
-25 : Q3
= : Итог
```

Если уровни соседних баров разные, линия рисуется **ступенькой**: половина
зазора по уровню первого бара, вертикальный отрезок, половина зазора по
уровню второго. Так видно, откуда именно «растёт» следующий шаг.

Нотация — как в Excel/McKinsey: линия выходит из **рабочего края** бара и
приходит в **стартовый край** следующего бара:

| Шаг | Выходит из | Приходит в |
|---|---|---|
| рост (`+`) | **верх** бара (уровень итога) | **низ** следующего бара |
| падение (`-`) | **низ** бара (уровень итога) | **верх** следующего бара |
| абсолютная колонка (`=`) | уровень её значения | уровень следующего бара |

Если уровни совпадают (обычный случай: итог после роста = старт следующего
шага), линия горизонтальная. Разные уровни соединяются ступенькой.

```
waterfall
y "" 0 --> 100
=20 : Старт
+30 : Рост
-40 : Падение
= : Итог
```

### Чёрно-белый режим (`mono`)

```
mono            # включить
mono invert     # светлые бары на тёмном холсте
mono off        # выключить
```

Все бары становятся серыми, различаются **светлотой**: итоги — тёмные,
рост — светлый серый, падение — средний серый. В тёмной теме светлота
разворачивается, чтобы бары были видны на тёмном фоне. `mono invert`
включает эту светлую шкалу сразу и затемняет холст — для тёмной темы
и для вставки в тёмный слайд. Явные `colors` перекрывают серую шкалу.

```
waterfall
mono
y "млн ₽" 0 --> 300
=120 : Q1
+80 : Q2
-40 : Q3
= : Итого H1
```

### Свои цвета (`colors`)

```
colors total=#hex increase=#hex decrease=#hex
```

| Ключ | Что красит | Синонимы |
|---|---|---|
| `total` | абсолютные колонки (старт, итоги) | — |
| `increase` | приращения вверх | `positive` |
| `decrease` | приращения вниз | `negative` |

- Ключи можно задавать в любом порядке и **по одному** — остальные берутся
  из палитры темы.
- Значение — `#rgb`, `#rrggbb` или простое имя цвета (`navy`, `teal`, …).
- В моно-режиме явные цвета перекрывают серую шкалу.

```
waterfall
colors total=#334155 increase=#0ea5e9 decrease=#f97316
y "млн ₽" 0 --> 200
=60 : Старт
+50 : Рост
-30 : Отток
= : Итог
```

### Мульти-режим (`series`)

```mermaid
waterfall-multi
title Два сценария
y "млн ₽" 0 --> 150
series Базовый
=50 : Старт
+30 : Рост
+20 : Итог
series Оптимистичный
=50 : Старт
+45 : Рост
+35 : Итог
```

- `series <имя> color=#hex` — базовый цвет группы.
- В мульти-серии цвет бара зависит и от группы, и от типа шага: итоги — базовый
  цвет группы, рост (+) — на 20 % светлее, падение (−) — на 25 % темнее.
  Так **все** бары различаются и по группе, и по типу.
- Без явных цветов базовые цвета групп всё равно различаются (в моно-режиме —
  разные уровни серого).
- Цвета отдельных групп можно задать и директивой: `colors s1=#hex s2=#hex`
  (синонимы ключей: `g1`, `series1`, `group1`). Явный `series <имя> color=`
  побеждает `colors sN=`.
- Каждый `series` открывает новую группу колонок.
- Группы рисуются рядом (grouped), подписи шагов берутся из **первой** группы.
- Если `series` не встречается ни разу — одиночный режим.
- Группа без строк данных — ошибка.

### Горизонтальные линии (`line`)

Уровни поверх диаграммы: план, цель, порог, среднее. Линия рисуется по всей
ширине графика **поверх баров, соединителей и подписей**, подпись — справа
от последнего бара, с вырезом под текст.

```
line <значение> ["подпись"] [color=#hex] [width=<px>] [style=solid|dash|dot|dashdot]
```

| Параметр | Значение | По умолчанию |
|---|---|---|
| `<значение>` | число в единицах оси Y | обязательно |
| `"подпись"` | текст справа от линии; кавычки не нужны, если нет пробелов | нет |
| `color` | `#rgb`, `#rrggbb`, имя цвета (`red`, `teal`), `rgb()/hsl()` | цвет текста темы |
| `width` | толщина в px, 0.5–12 (`2px` тоже принимается) | 1.5 |
| `style` | `solid`, `dash`, `dot`, `dashdot` | `dash` |

```
waterfall
title Выручка против плана
y "млн ₽" 0 --> 500
grid 100
line 350 "план"
line 400 "цель" color=#cf222e width=2
line 250 "порог" style=dot width=1
=120 : Q1
+180 : Q2
-60 : Q3
= : Итого H1
```

Порядок параметров любой, подпись может стоять до или после них.
Линий может быть сколько угодно — каждая отдельной строкой.

**Запись прощает распространённые варианты** (всё это одно и то же):

| Пишут так | Тоже верно |
|---|---|
| `line: 350`, `line=350`, `line +350` | `line 350` |
| `line 350, "план"` | `line 350 "план"` |
| `line 350 план` (без кавычек) | `line 350 "план"` |
| `stroke=#cf222e`, `colour=red` | `color=#cf222e`, `color=red` |
| `thickness=2`, `width=2px` | `width=2` |
| `style=dashed`, `style=--`, `dash`, `dashed` | `style=dash` |
| `line 350 "план" #cf222e` | `line 350 "план" color=#cf222e` |

Линия внутри вырезанного `break` прижимается к ближайшей границе разрыва —
на шкале такого значения нет, и рисовать её «в пустоте» было бы неверно.
Линия за пределами `y`-диапазона не рисуется.

### Ошибки

| Условие | Сообщение |
|---|---|
| нет ни одной строки данных | `нет данных: ожидается хотя бы одна строка «=N : подпись»` |
| первая колонка не `=` | `первая колонка должна быть абсолютной (=N)` |
| первая колонка `=` без значения | `первая колонка должна быть абсолютной со значением (=N)` |
| `+`/`-` без числа | `после «+» ожидается число (пустое значение допустимо только для «=»)` |
| `break` с «до» ≤ «после» | `разрыв: «до» (<a>) должно быть больше «после» (<b>)` |
| пересекающиеся `break` | `разрывы пересекаются: «…» и «…»` |
| неверный `grid` | `ожидается «grid <положительный шаг>», получено «…»` |
| неверный `labels` | `ожидается «labels above\|inside\|both\|none», получено «…»` |
| неверный `connectors` | `ожидается «connectors on» или «connectors off», получено «…»` |
| неверный `fontsize` | `ожидается «fontsize <положительное число>», получено «…»` |
| непарсящееся число | `не удалось разобрать число: «<фрагмент>»` |
| нет `:` в строке данных | `ожидается формат «<знак><число> : подпись»` |
| `line` без числа | `ожидается «line <значение> ["подпись"] [color=#hex] [width=<px>] [style=dash]», получено «…»` |
| `line` с неверным цветом | `не удалось разобрать цвет линии «…» (ожидается #rgb, #rrggbb или имя цвета)` |
| `line` с неверной толщиной | `толщина линии: ожидается положительное число, получено «…»` |
| `line` с неверным стилем | `стиль линии: ожидается solid\|dash\|dot\|dashdot, получено «…»` |
| `series` без данных | `группа «<имя>» не содержит данных` |
| неверный `mono` | `ожидается «mono», «mono invert» или «mono off», получено «…»` |

## 2. `bubble` — пузырьковая

Три измерения: `x`, `y`, `size`. Опционально — квадранты (BCG) и группы (цвет).

```mermaid
bubble
title BCG матрица
x "Доля рынка" 0 --> 10
y "Рост рынка, %" 0 --> 30
size "Выручка"
quadrants Звёзды, Вопросы, Дойные коровы, Собаки
mid x=5 y=12
data
Продукт A : x=8.2, y=22, size=340, group=Software
Продукт B : x=2.1, y=25, size=180, group=Software
```

### Директивы

| Строка | Смысл |
|---|---|
| `title <текст>` | заголовок |
| `x "<подпись>" <min> --> <max>` | ось X, обязательна |
| `y "<подпись>" <min> --> <max>` | ось Y, обязательна |
| `size "<подпись>"` | подпись легенды размера |
| `quadrants <q1>, <q2>, <q3>, <q4>` | 4 подписи квадрантов (порядок: ↖ ↗ ↙ ↘) |
| `mid x=<num> y=<num>` | линии раздела квадрантов; без неё — середина диапазона |
| `fontsize <px>` | размер шрифта подписей точек (по умолчанию 11, допустимо 6–28) |
| `mono` / `mono invert` | чёрно-белый режим групп (см. §0) |
| `data` | начало блока точек (обязателен) |

### Подписи

Подписи точек выводятся **целиком** — никогда не обрезаются «…».
Если блок текста влезает в круг, он стоит по центру пузырька и переносится
по словам. Если не влезает (длинная подпись или мелкий круг), вся подпись
рисуется **под пузырьком**, тоже переносом по словам и без разрезания слов.
Подписи квадрантов остаются внутри своей четверти и переносятся по словам.

Размер шрифта задаётся директивой `fontsize <px>`:

- по умолчанию **11 px**;
- допустимый диапазон — **6–28 px** (значения вне диапазона прижимаются к краю);
- масштабируются все тексты: подписи точек, легенда, подписи осей,
  квадранты и заголовок (заголовок и оси — мягче, чтобы не съедать шапку);
- шрифт подписи точки не уменьшается, чтобы втиснуть её в круг:
  не влезла — уходит под пузырёк.

```
bubble
title Крупные подписи
x "Охват" 0 --> 100
y "Конверсия, %" 0 --> 20
fontsize 16
data
Кампания в поиске : x=12, y=8.5, size=50
```

### Строки данных

```
<подпись> : x=<num>, y=<num>, size=<num>[, group=<имя>]
```

- Порядок ключей `x`, `y`, `size` фиксирован; `group` — последний и опционален.
- `size` — относительный вес, не радиус. Радиус = линейное масштабирование
  от минимального к максимальному весу в наборе, с ограничением
  `r ∈ [6, 40]` px (при `debugFrames` — те же).
- Точка вне диапазона осей **не обрезается**, а прижимается к краю с пометкой
  в консоли (в прод-сборке — молча).

### Ошибки

| Условие | Сообщение |
|---|---|
| нет `x` или `y` | `не задана ось «x»` / `не задана ось «y»` |
| нет блока `data` | `не найден блок «data»` |
| нет точек | `блок «data» пуст` |
| неизвестный ключ | `неизвестный ключ «<ключ>» в строке точки` |
| `quadrants` ≠ 4 | `ожидается 4 подписи квадрантов, получено <n>` |

## 3. `heatmap` — тепловая карта

Матрица значений `y × x` с цветовой шкалой.

```mermaid
heatmap
title Нагрузка по дням
x Пн, Вт, Ср, Чт, Пт
y Утро, День, Вечер
scale
0-40 : #e8f5e9

70+ : #ffebee
data
Утро : 20, 35, 50, 30, 25
День : 60, 75, 85, 70, 55
Вечер : 40, 45, 65, 50, 35
```

### Директивы

| Строка | Смысл |
|---|---|
| `title <текст>` | заголовок |
| `x <a>, <b>, ...` | подписи колонок (порядок слева направо) |
| `y <a>, <b>, ...` | подписи строк (порядок сверху вниз) |
| `scale` | начало блока цветовой шкалы |
| `mono` / `mono invert` | серый ряд вместо цветов шкалы (см. §0) |
| `data` | начало блока значений |

### Блок `scale`

```
<от>-<до> : <цвет>
<от>+ : <цвет>
```

- Диапазоны **не пересекаются** и покрывают всю шкалу без дыр (проверяется).
- Верхняя граница включительна, нижняя — исключительна
  (`40-70` → `[40, 70)`, `70+` → `[70, ∞)`).
- Цвет — `#rgb`, `#rrggbb` или CSS-имя. Валидируется через `CSS.supports` при
  наличии DOM, иначе — регуляркой.
- Если `scale` отсутствует — используется встроенная 5-ступенчатая шкала
  (зелёный → жёлтый → красный) по min/max данных.

### Строки данных

```
<подпись строки> : <v1>, <v2>, ...
```

- Число значений обязано совпадать с числом колонок `x`.
- Пустая ячейка — два разделителя подряд (`20,,35`) — трактуется как `null`,
  рисуется серым, в min/max не участвует.
- Подпись строки обязана совпасть с одной из строк `y` (иначе — ошибка).

### Ошибки

| Условие | Сообщение |
|---|---|
| нет `x` или `y` | `не заданы подписи оси «x»` / `... «y»` |
| нет `data` | `не найден блок «data»` |
| несовпадение длины | `строка «<имя>»: ожидается <n> значений, получено <m>` |
| неизвестная строка | `строка «<имя>» отсутствует в списке «y»` |
| дыра/пересечение в scale | `шкала не покрывает значение <v>` / `диапазоны шкалы пересекаются` |

## 4. `orgchart` — оргструктура

Дерево с явными рёбрами и защитой от циклов.

```mermaid
orgchart
Гендиректор [Генеральный директор\nИван Петров] color=#8250df
Техдир [Технический директор\nАнна Смирнова] color=#ddf4ff border=#0969da
Финдир [Финансовый директор\nОльга Орлова] border=#9a6700 style=dash
Бэкенд [Руководитель серверной разработки\nСергей Волков]
Фронтенд [Руководитель клиентской разработки\nМария Соколова]
Гендиректор -> Техдир
Гендиректор -> Финдир
Техдир -> Бэкенд
Техдир -> Фронтенд
Финдир -.-> Бэкенд
```

### Директивы

| Строка | Смысл |
|---|---|
| `<id> [<подпись>]` | объявление узла; `id` — без пробелов, `\n` в подписи переносит строку |
| `<id> [<подпись>] color=#hex` | заливка блока. Синонимы ключа: `fill`, `colour`. Имя цвета тоже подходит: `color=red` |
| `<id> [<подпись>] border=#hex` | цвет границы. Синоним: `stroke`. Если цвета нет, а заливка задана — граница совпадает с заливкой |
| `<id> [<подпись>] style=dash` | стиль границы: `solid`, `dash` (`dashed`), `dot` (`dotted`), `dashdot`. Коротко: `border=dash` |
| `<id> [<подпись>] width=2` | толщина границы в px (0.5–8). Синонимы: `thickness`, `border-width` |
| `<id1> -> <id2>` | обычное ребро (сплошная линия) |
| `<id1> -.-> <id2>` | пунктирное ребро (dotted, «второй руководитель») |
| `mono` / `mono invert` | серые блоки (см. §0) |

Цвет и стиль независимы: можно задать только заливку, только границу или оба сразу. Порядок ключей любой, значения можно брать в кавычки (`color="#1f6feb"`). Параметры пишутся **после** `]`: внутри скобок `color=` остаётся текстом подписи. Текст на цветной заливке подбирается контрастным.

```mermaid
orgchart
Гендиректор [Генеральный директор\nИван Петров] color=#8250df
Техдир [Технический директор\nАнна Смирнова] color=#ddf4ff border=#0969da style=dash
Финдир [Финансовый директор] border=#9a6700 width=2
Гендиректор -> Техдир
Гендиректор -> Финдир
```

- `id` — латиница/кириллица/цифры/`_`/`-`, без пробелов.
- Подпись в `[...]` опциональна; без неё подписью служит `id`.
- `\n` внутри подписи разбивает текст на несколько строк; размер блока (ширина и высота) подгоняется под текст целиком без обрезки `…`.
- `[` и `]` внутри подписи экранируются как `\[` / `\]`.
- **Корень** — узел без входящих рёбер. Если корней несколько —
  создаётся виртуальный корень (невидимый) и все они становятся его детьми.
  Если корней нет (цикл) — ошибка.
- Раскладка — **Reingold–Tilford** (собственная реализация, ~150 строк,
  без `d3-hierarchy`). Приоритет — читаемость, не пиксельная точность.
- **Защита от циклов:** ребро, замыкающее цикл, не ломает раскладку —
  оно рисуется как обычное, но узел **не** посещается повторно в DFS.
  Если цикл делает граф неприводимым к дереву (нет корня) — ошибка.
- Порядок детей = порядок объявления рёбер.

### Ошибки

| Условие | Сообщение |
|---|---|
| нет рёбер | `нет рёбер: ожидается «A -> B»` |
| ребро на необъявленный узел | узел создаётся неявно (не ошибка) |
| нет корня (все в цикле) | `не найден корень: все узлы входят в циклы` |
| невалидный `id` | `недопустимый идентификатор узла: «<id>»` |
| дубль объявления | последнее объявление побеждает, предупреждение в консоль |
| плохой цвет блока или границы | `не удалось разобрать цвет блока` / `граница блока: ожидается цвет...` |
| плохой стиль границы | `стиль границы: ожидается solid\|dash\|dot\|dashdot` |
| неизвестный параметр узла | `неизвестный параметр узла «...»` |

## 10. `series` — серийная диаграмма с опцией поворота на 90°

Сгруппированные столбцы нескольких серий по категориям. Первая строка — только `series`. Директива `rotate 90` (синонимы `rotate`, `horizontal`, `orientation horizontal`) поворачивает диаграмму на 90 градусов (категории сверху вниз слева, полосы растут слева направо).

`stacked` (синонимы `bars stacked`, `layout stacked`) складывает серии в **один** столбец: положительные значения растут вверх от нуля, отрицательные — вниз. `stacked off` или `bars grouped` возвращает бары рядом. Шкала сама расширяется до суммы сегментов, если `y` не задан.

`mono` и `mono invert` — чёрно-белый режим, см. §0.

В списке значений серии и линии можно пропустить категорию: пустой слот между запятыми, `-` или `null`. Пропуск в серии не рисует бар. Пропуск в линии не разрывает её: точка до пропуска соединяется с точкой после.

```
series
title Состав выручки
stacked
categories Q1, Q2, Q3, Q4
y "млн ₽" 0 --> 400
series Продукт : 80, 90, 70, 110
series Услуги : 50, 60, -, 70
line План : 140, 160, 150, 190 color=#1f2328 style=dash
cagr
```

### Линия (`line`)

Ломаная по категориям поверх столбцов. Подпись (текст до двоеточия) рисуется справа от края зоны графика, на высоте последней заданной точки.

```
line <подпись> : зн1, зн2, … [color=#hex] [style=solid|dash|dot|dashdot] [width=<px>]
```

| Параметр | Значение | По умолчанию |
|---|---|---|
| подпись | текст справа от графика | нет |
| значения | по одному на категорию; `-`, пусто или `null` — пропуск, соседние точки соединяются | обязательно |
| `color` | `#rgb`, `#rrggbb`, имя цвета | цвет текста темы |
| `style` | `solid`, `dash`, `dot`, `dashdot` | `solid` |
| `width` | толщина в px, 0.5–12 | 1.75 |

### CAGR (`cagr`)

Стрелка между двумя барами одной серии и овал с процентом. Несколько строк `cagr` подряд относятся к одной серии: к серии, которая объявлена непосредственно перед ними, а если `cagr` стоит до любой серии — к первой.

`cagr` без номеров соединяет первый и последний бар. `cagr 1, 5` соединяет бар 1 и бар 5 (номера с единицы, в пределах одной серии).

Процент — CAGR за число шагов между барами, по умолчанию округление до целого: `30%`. Если старт или финиш не положительные, в овале `н/д`.

| Параметр | Эффект |
|---|---|
| `format="0.0%"` | шаблон числа; `0%` — целое, `0.0%` — один знак, `%` включает проценты. `+` и `±` (`±0`, `±0.0%`) добавляют плюс только к положительному числу; у отрицательного остаётся минус, плюс не пишется |
| `prefix="CAGR: "` | приписывается перед числом: `CAGR: 12.1%` |
| `label="рост"` | овал показывает эту строку как есть, без расчёта |

`label` заменяет и число, и `prefix`.

Все параметры линии в одном примере: четыре `style`, свой `color` и `width`, пропуск через `-`, пустой слот и `null`.

```
series
title Факт и ориентиры
categories Q1, Q2, Q3, Q4
y "млн ₽" 0 --> 220
series Факт : 120, 145, 165, 190
line Сплошная : 110, 130, 150, 180 color=#0969da style=solid width=2
line Пунктир : 100, -, 160, 175 color=#8250df style=dash
line Точки : 90, , 155, 170 color=#2da44e style=dot width=1
line Штрих-точка : 80, 120, null, 160 color=#f97316 style=dashdot width=2.5
```

Простой `cagr` без номеров: стрелка от первого бара серии к последнему.

```
series
title Рост выручки
categories 2021, 2022, 2023, 2024
y "млн ₽" 0 --> 220
series Выручка : 80, 110, 150, 190
cagr
```

Стрелки, которые не пересекаются, рисуются на одном уровне. Общий конец диапазона пересечением не считается: `cagr 1, 3` и `cagr 3, 4` стоят рядом, а `cagr 2, 4` уходит выше, потому что пересекает обе.

Разные опции на соседних диапазонах: целое, доля с `prefix`, дробь с `prefix`, `label`, плюс в шаблоне и `prefix` у падения. Несколько `cagr` подряд относятся к серии, объявленной прямо перед ними. `label` заменяет и число, и `prefix`.

```
series
title CAGR по диапазонам
ratio 16x6
categories 2017, 2018, 2019, 2020, 2021, 2022, 2023, 2024, 2025
y "млн ₽" 0 --> 220
series Онлайн : 34, 39, 68, 74, 90, 108, 118, 140, 130
cagr 1, 2 format="0%"
cagr 2, 3 format="0.00" prefix="×"
cagr 3, 5 format="0.0%" prefix="CAGR: "
cagr 5, 6 label="цель"
cagr 8, 9 format="+0.0%"
cagr 6, 7 format="0%" prefix="+"
```

## 11. Что НЕ входит в v1

Зафиксировано осознанно, чтобы не расползался объём:

- **Никаких контактов автора, водяных знаков, ссылок** в SVG.
- `ishikawa` (рыбья кость) — **не входит**. В v1 пять типов, ровно те, что выше.
  Ishikawa v2 обсуждался отдельно; если появится — это отдельный этап, не «дописать в ev».
- Интерактивность (tooltip, hover, клики) — нет, только статичный SVG.
- Анимация — нет.
- Экспорт в PNG — на уровне приложения (этап 7), не в движке.

### Прозрачный фон

Фон диаграммы — свойство **приложения**, а не синтаксиса: движок всегда рисует
палитру темы (светлую или тёмную — по `dark`), а прозрачность включается в тулбаре
предпросмотра (кнопка «Прозрачный фон», иконка глаза).

- Превью показывает шахматку вместо цвета — видно, что фон пустой.
- **SVG-экспорт** снимает плашку на весь холст (`fill="none"`), содержимое не трогается.
- **PNG-экспорт** не заливает полотно: альфа-канал сохраняется.
- `dark` из темы диаграммы прокидывается в палитру всех движков, поэтому на
  прозрачном фоне тёмная тема остаётся читаемой (светлые подписи, тёмная сетка).

## 7. Контракт движка

```ts
interface ExtEngine<T> {
  type: ExtDiagramType;
  aliases: string[];
  parse(source: string): ExtParseResult<T>;   // никогда не бросает
  render(model: T, options: ExtRenderOptions): string; // SVG-строка
}
```

- `parse` **никогда** не бросает — только `{ ok: false, errors }`.
- `render` получает уже валидную модель; при внутренней ошибке бросает `Error`.
- SVG-корень: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H" ...>`,
  без `width`/`height` в атрибутах — размер задаёт контейнер.
- Все текстовые узлы — `<text>` с `font-family` из темы; измерение текста —
  **без DOM** (собственная таблица ширин по глифам, см. этап 2).
- `options.dark` меняет палитру, `options.debugFrames` добавляет обводку
  каждому элементу и его `id` в `data-*`.

## 8. Проверка и обновление оффлайн-рендеров

Два скрипта закрывают класс ошибок «No diagram type detected matching given
configuration» — когда движок расширения не подключён к рендеру и исходник
уходит в штатный `mermaid.parse`.

### `npm run ext:preflight` — проверка актуальности

```bash
node scripts/mermaid-ext-preflight.mjs                 # все слои
node scripts/mermaid-ext-preflight.mjs --json          # машинный отчёт
node scripts/mermaid-ext-preflight.mjs --report=out.md # markdown-таблица
node scripts/mermaid-ext-preflight.mjs --skip=dist     # без проверки бандла
```

Слои (от дешёвого к дорогому):

| Слой | Что ловит |
|---|---|
| `build` | `__MERMAID_EXT__` захардкожен в `false` → движок вырезан tree-shaking'ом |
| `entries` | точки входа (движок, синтаксис, хендлер, модуль языка) не собираются |
| `wiring` | `tryRenderExtension()` не рисует свой тип или перехватывает чужой |
| `detect` | `detectSource()` не знает ext-ключевых слов → текст уходит в PlantUML |
| `fence` | `isMermaidExtDeclaration()` не видит тип внутри ```` ```mermaid ````-блока |
| `golden` | эталоны `sandbox/golden/` разошлись с текущим рендером |
| `samples` | сэмпл из каталога приложения (ru/en) не рисуется |
| `dist` | собранный бандл без движка ext (устарел) |

Выход `1` — есть расхождения. Время: ~10 с без `entries`, ~40 с целиком.

### `npm run ext:refresh` — замена устаревших рендеров

```bash
node scripts/mermaid-ext-refresh.mjs            # только расходящиеся
node scripts/mermaid-ext-refresh.mjs --dry-run  # показать, что изменится
node scripts/mermaid-ext-refresh.mjs --all      # перезаписать все эталоны
node scripts/mermaid-ext-refresh.mjs --only=waterfall,ev
node scripts/mermaid-ext-refresh.mjs --verify   # обновить и сразу прогнать preflight
```

- Перед записью делает копию в `sandbox/golden.bak/<дата>/` (`--no-backup` в CI),
  в конце печатает команду откатa.
- Пишет **только изменившиеся** файлы — git-история остаётся чистой.
- Удаляет осиротевшие эталоны (фикстуру убрали — файл тоже).
- Битые фикстуры дают эталон вида `ERROR: …` — это норма, не ошибка прогона.

Типовой цикл после правки движка:

```bash
node scripts/mermaid-ext-refresh.mjs --verify
git add sandbox/golden && git commit -m "chore(mermaid/ext): обновить эталоны"
```
